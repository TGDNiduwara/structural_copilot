## 2. Instability type 3 - what headless actually does
Evidence, not assumption:
- The live dialog text (probe6 window capture) is: "Instability type 3"
  warning ... with Yes/No/Cancel and a link to Autodesk's article "Can
  instability type 3 error be ignored in Autodesk Robot Structural
  Analysis". The official article itself could NOT be fetched (403/404 on
  every mirror tried), so its exact wording is not quoted here.
- headless (HeadlessSession) sets robot_app.Interactive=0 in connect()
  (headless_driver.py L152). grid.log across 100 candidates contains ZERO
  'instabilit' mentions - the prompt is suppressed, not answered.
- Interactive=1 shows the dialog: 'No' -> ALL results silently zero;
  'Yes' -> correct results. probe7 (interactive + Yes) produced EXACTLY the
  same numbers as probe4 (headless): reactions 25.407 + 25.407 = 50.814 kN
  vs 50.8138 kN applied (0.00% error), member forces non-zero.
- CONCLUSION: headless default is genuinely equivalent to "continue" (the
  underlying numerical condition - a planar structure in a 3D project has
  unrestrained out-of-plane DOFs - IS present; Interactive=0 suppresses the
  prompt and Robot proceeds). It is NOT that headless never encounters it.
  This is verified by identical results, not assumed.
- Forward flagging: _guarded_calculate now records instability_seen and the
  solve tool returns status="ok_with_warning" with an explicit warning the
  LLM/user is forced to see; also logged at WARNING level. Never silent.

## 3. Did the apply_self_weight / export_structure_spec bugs affect Phase-A?
CONFIRMED NO (by source inspection, not assumption):
- batch/runner.py _evaluate_candidate uses: build_from_spec (loads applied
  via apply_bar_load from spec 'loads' list), session.solve_all,
  get_weight (BOQ), get_utilization_summary, _buckling_for_candidate.
  It NEVER calls apply_self_weight or export_structure_spec.
- The grid/surrogate world (validate_surrogate_live.make_spec) defines
  loads as bar_uniform -25 kN/m on bar 2; those flow through apply_bar_load.
- apply_self_weight and export_structure_spec are only used by chat tools /
  the backlog checks; their bugs (self-weight value; load read-back) could
  not have touched any grid/surrogate number.
- CAVEAT discovered while confirming: the SURROGATE logged util=0.0
  (per-bar N/A) for candidates 49 & 68, both AFTER the 19:08 reconnect,
  while the GRID scored the SAME designs at util 0.2242 / 0.3092. This is a
  zero-results data-quality caveat in the surrogate run. Quantified impact
  on the reported HV: NIL - the phantom margin=1.0 lies on the normalizer
  reference axis, so hv_corrected == hv_reported == 1.5568 (ratio 0.9566).
  The EHVI run had ZERO util=0.0 rows, so its hv_ratio 1.0000 is clean.
